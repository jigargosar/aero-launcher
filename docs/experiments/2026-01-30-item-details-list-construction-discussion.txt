  ├────────────┼───────────────────────────────────────────────────┤
  │ Contacts   │ Details (email, phone, address) - each actionable │
  ├────────────┼───────────────────────────────────────────────────┤
  │ Folders    │ Contents (files, subfolders)                      │
  ├────────────┼───────────────────────────────────────────────────┤
  │ Text Files │ Line/paragraph content                            │
  ├────────────┼───────────────────────────────────────────────────┤
  │ URLs       │ Other URLs from same domain                       │
  ├────────────┼───────────────────────────────────────────────────┤
  │ Playlists  │ Tracks                                            │
  └────────────┴───────────────────────────────────────────────────┘
  Key Insight

  Contacts pattern is closest to what you want:
  - Contact → Right Arrow → details list (email, phone, address)
  - Each detail is actionable (email opens composer, phone shows large type)
  - Preferred item shown first

  LaunchBar does NOT show app metadata - it shows recent docs.

  Your Ask vs LaunchBar

  LaunchBar apps: App → Right Arrow → Recent Documents
  Your ask: App → Right Arrow → Metadata (path, version, AppID)

  Recommended Pattern (Contact-style)

  App → browse (Right Arrow) → metadata items:
    - Path: C:\...        (execute = copy, actionMenu = reveal)
    - AppID: com.foo      (execute = copy)
    - Version: 1.0.0      (execute = copy)

  Each metadata item is actionable like contact details.

  Alternative: Action Menu (Ctrl-Right Arrow)

  LaunchBar's action menu (Ctrl-Right Arrow) already shows context actions:
  - Open, Rename, Move to Trash, etc.

  Could add metadata display there instead of browse.

  ---
  Which pattern?
  1. Browse (Right Arrow) - metadata as sublist like contacts
  2. Action Menu - metadata alongside actions
